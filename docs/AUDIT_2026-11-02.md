# FUNAAB Workforce — Code Audit (2 Nov 2026)

## 1. What the project is

A Laravel 10 / PHP 8.1 / MySQL HR system for FUNAAB Registry (Personnel Records & Statistics). It has four portals:

| Portal | URL | Purpose |
|---|---|---|
| Staff | `/` → `/staff/*` | Sign-up (checked against the Nominal Roll), profile, **APER forms**. The same login also opens the Supervisor, HOD and Chairman DAPC assessor views. |
| Admin | `/admin/*` | Staff records (personal and employment), lookups (states, LGAs, zones, divisions, departments, titles, categories, statuses…), progression (salary structures, levels and steps, cadres, ranks, designations, promotions, step increments), leave, APER windows and assessor assignment |
| Identity | `/identity/*` | Read-only staff lookup for identity verification |
| Guest staff update | `/staff_updates/*` | Self-service data-update flow from the nominal roll |

**APER workflow as built**

- **Junior Non-Teaching**: Staff Part A (personal) → Part B (duties) → Supervisor (sick leave, health centre, sanctions) → HOD (items 17–19 and recommendation 21) → Staff comment (item 20) → Chairman DAPC (scoring and endorse/reject, only for staff the HOD recommended for promotion).
- **Senior Non-Teaching**: A1 Personal → A2 Education → A3 University experience → HOD → Staff comment (Part C) → Chairman DAPC.
- **Academic staff**: not built yet.

The codebase also carries leftover modules from an earlier "WorkPlace" app: Circles, Cells, Documents/Workflow, Ministries, Deans, Tracker and Messages. Their models and tables do not exist.

| # | Issue | Where |

## 3. APER module: errors and gaps

**Errors**

| # | Issue |
|---|---|
| A1 | There is **no final "Submit" or lock step**. While the window is open, staff can keep editing Part A and Part B even after the Supervisor or HOD has evaluated them. Assessors can also re-edit after the next stage has acted. |
| A2 | **Stage order is not enforced.** The HOD can assess before the Supervisor. The staff comment (Part C) can be posted before the HOD evaluates, and it has no window-open check. The Chairman does not check that the staff comment exists. |
| A3 | There is **no per-staff status record** (e.g. `aper_submissions`: draft → submitted → supervisor_done → hod_done → staff_commented → dapc_done). Status is inferred from whether child rows exist, which is fragile and slow. |
| A4 | Each `updateOrCreate` call writes `uuid => Str::uuid()` in the update array, so the record's UUID **changes on every save**. |
| A5 | The per-staff APER tables have **no unique `(aper_form_id, staff_id)` index**, so a double submit can create duplicate rows. Part saves use delete-then-insert **without a DB transaction**. |
| A6 | **Deleting an APER window from Admin cascade-deletes every submission** linked to it. It should be blocked or soft-deleted once submissions exist. |
| A7 | Supervisor results are looked up with `supervisor = current supervisor`. If the supervisor is reassigned, the staff member's evaluation "disappears". |
| A8 | `getSupervisorRecord()`, `getHodRecord()` and `getChairmanRecord()` use `->first()`. Someone who is HOD of two departments, or of both Junior and Senior, only sees one. The HOD's `staff_category_id` is ignored in the staff list. |
| A9 | `juniorCategoryId(): int` throws a TypeError if no category name contains "Junior". |
| A10 | Junior Part A uses non-null-safe chains (`employment->salaryStep->salaryLevel->salaryStructure`, `date_funaab_first_appointment->format()`). The log shows repeated *"property … on null"* crashes for staff with incomplete employment data. |
| A11 | Staff lists run 1–2 queries per staff member inside `->filter()` (N+1), which will be slow at department scale. |
| A12 | Route `staff/supervisor/{aperForm}/submission/{staff}/aper_junior_part_b` points to `submission_part_b()`, which doesn't exist. |
| A13 | Routes defined as `staff/aper/...` inside the `staff` prefix resolve to `/staff/staff/aper/...`, which is inconsistent with the other routes. |

**Gaps (not built)**

| # | Gap |
|---|---|
| G1 | **Academic Staff APER** is not built (738 of 2,421 staff on the nominal roll). |
| G2 | **Senior Non-Teaching has no Supervisor stage** (Junior has one). This needs confirming against the official form. |
| G3 | There is **no admin screen for scoring guides or promotion minimum requirements**, which the Chairman scoring depends on. |
| G4 | Admin has **no APER progress dashboard** (who has submitted or is pending at each stage, by department) and **no reports or exports** (Excel/PDF), A&PC promotion lists, or a printable APER form. |
| G5 | There are **no notifications** (email or in-app) when a stage is completed or the window opens or closes. |
| G6 | There is **no promotion eligibility check** (years on grade, salary level minimums) and no link from APER results to the `promotions` table. |
| G7 | There is **no audit trail** of who changed what during assessment. |

## 5. Nominal roll (July 2026) vs. the system

## 7. Proposed completion roadmap

1. **Stabilise**: fix C1–C10 and A4/A5/A9/A10/A12; add seeders; remove legacy modules (or rebuild them if still wanted); add the nominal roll importer (N1–N3).
2. **APER engine**: add an `aper_submissions` status table, stage gating and locking, authorisation policies (C3, A1–A3, A7, A8), and unique indexes plus transactions.
3. **Complete the forms** against the official APER documents: verify Junior and Senior field by field, build the Academic APER, and add the Senior Supervisor stage if the form requires it.
4. **Admin**: scoring guides and min-requirements UI, a progress dashboard, reports (Excel/PDF), a printable APER, and notifications.
5. **Remaining modules**: missing lookup CRUD methods, staff leave application, disengagement (off-employment), analytics.

## 8. Addendum: live database dump (`funaab_workforce_fixed.sql`, 2 Nov 2026)

The dump was loaded into MariaDB and compared, column by column, with a database built from the code's own migrations.

**Schema drift (the code and the live DB disagree)**

| # | Finding | Impact |
|---|---|---|
| D1 | Three migrations are **not recorded** in the live `migrations` table (`add_geo_zone_to_staff…`, `add_createdby_to_staff`, `add_createdby_to_employment`), but their columns **already exist**. | Running `php artisan migrate` on the live DB will fail with duplicate-column errors. |
| D2 | 16 legacy migrations (cells, circles, documents, workflows, messages, ministries, deans, announcements, categories) are recorded in the DB and their **tables exist (all empty)**, but the migration files and models are **gone** from the code. | This corrects C7: the tables exist but the models don't, so those pages still crash. They should be removed cleanly (a drop migration) or rebuilt. |
| D3 | The code's `create_*` migrations have `uuid` on 9 lookup tables, but the **live DB does not**: contact_types, divisions, division_types, marital_statuses, states, staff_categories, geo_pol_zones, lgas (plus profiles.bio and staff_updates names). | **Creating a Division in Admin fails on the live DB**: `Admin_DivisionController@store` writes `uuid`. Fresh installs and the live DB have different schemas. |
| D4 | Nullability and type differences: `staff_categories.parent_staff_category` is NOT NULL in code but NULL in live (the "Academic" and "Non-Teaching" rows need it NULL). `employments.employment_type_id` is NOT NULL in code but nullable in live. `staff_updates.dob` is varchar in live but date in code. `profiles.designation/phone/avatar` are NOT NULL in live (so creating a profile can fail). `users.fileno` is varchar(10) in live. `promotions.status` and `profiles.home_address` exist only in live. | A fresh install will reject live data. ## 9. Official APER forms vs. the system (Senior Non-Teaching and Junior CONTISS 01–05)

Source: "Aper Form – New Senior.pdf" (12 pages; Senior is pp. 1–5, Junior pp. 6–12).

**What the official forms confirm**

- **Senior has no Supervisor stage.** Its flow is Staff (Part A, items 1–16) → HOD (Part B, items 17–19 and 21) → Staff comment (item 20) → Departmental Assessment Panel scoring (Part C, items 22–23). G2 is closed: nothing needs adding.
- **Junior's flow is** Staff (Part A, items 1–11, and Part B, items 12–14, then the staff signs) → Supervisor (items 15–16) → HOD (Part C, items 17–19 and 21) → Staff comment (item 20) → Panel scoring (item 22) → Departmental A&PC endorse/reject (item 23).
- The existing table structure already matches most of both forms. The Senior HOD's 9 grades (a–i) and the "agree on job description" YES/NO are present.

**Mismatches to fix**

| # | Form | Issue |
|---|---|---|
| F1 | Both | **Reporting period (1 Oct – 30 Sep) is not stored.** `aper_forms` only has the submission window. Add a review-period start and end, and print it on the form. |
| F2 | Both | **Item 7, "Date & Post of Last Promotion"**, is prefilled from the *present* appointment. It should come from the latest `promotions` record (that table is empty), with item 8 as the current appointment. |
| F3 | Senior | **Scoring guide is missing "(vii) Commendations – 5"**, so the DB totals 95, not 100. Also fix the corrupted character in "Head of Department's". |
| F4 | Junior | **The scoring guide has 1 metric; the form has 9.** They are: Qualifications 10, Conduct 10, Initiative 15, Punctuality & Regularity 10, Self-improvement 5, Human Relations 5, Degree of Reliability 10, Commendation 5, HOD's Assessment 30 (total 100). |
| F5 | Senior | **Minimum promotion scores:** CONTISS 07 = 40, 08 = 45, 09 = 50, 10 = 52, 11 = 55, 12 = 57, 13 = 60, 14 = 65, 15 = 70. The DB has 1 row. |
| F6 | Junior | **Minimum promotion scores:** CONTISS 01 = 45%, 02 = 50%, 03 = 55%, 04 = 60%, 05 = 65%. The DB has 1 row, and CONTISS 01–05 salary levels don't exist yet. |
| F7 | Both | **"HOD's Assessment" should be calculated, not typed in.** The Senior HOD grades 9 items × 5 = 45, which equals the 45-mark metric; the Junior HOD grades 6 items × 5 = 30, which equals the 30-mark metric. The system should fill these in from the HOD's grades. Likewise "Managerial Ability" (Senior) and "Degree of Reliability" (Junior) are "based on HOD's assessment of organizational ability" and can be derived (grade × 2). |
| F8 | Both | **The 70% punctuality and regularity rule is not built.** Staff who don't reach 70% are not eligible for promotion or the annual increment. |
| F9 | Both | **Promotion should use the APERs from the last 3 years**, so a 3-year view per staff member is needed. |
| F10 | Junior | Item 15 frequency labels: the form prints "11 – 12 Units", which is almost certainly a typo for **11 – 20**. The code copies the typo. |
| F11 | Junior | Item 11 asks for "subjects and grade of passes". There is no field for it. |
| F12 | Senior | Item 12 asterisk: there is no flag for "additional qualification during the period under review". |
| F13 | Senior | Item 13(b) Practicals is **for Academic Technologists only**, but it is shown to every senior staff member. |
| F14 | Senior | Item 21(ii), "Salary increment by ___ Steps", is stored as a salary-step ID instead of a number of steps. |
| F15 | Senior | The official Part C has **no endorse/reject section** (only Junior item 23 has one), but the system asks for it. Keep it as optional, or remove it? |
| F16 | Both | **Signatures and dates at each stage** (staff, supervisor, HOD, panel chairman) should be recorded as who-signed and when on the new status record (A3). |
| F17 | Both | Which form a staff member gets should follow **salary level** (CONTISS 01–05 = Junior), not only the staff category name. |

**Still needed:** the APER form for **Academic Staff**.
